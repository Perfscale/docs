## Обзор

Модуль GOST генерирует криптографические тестовые данные для сервисов, которые
ожидают алгоритмы ГОСТ: государственные шлюзы, банковские интеграции и системы,
проверяющие входные данные Кузнечик, Магма или Streebog. Он полезен для
разнообразия payload, проверки стандартных векторов и детерминированных
нагрузочных сценариев.

Это **платная** возможность (тарифы Scale и Enterprise). Она включена в сборку
agent `pro-full`; минимальная сборка может включать только `pro-gost`.

Модуль генерирует данные — он **не** реализует GOST TLS, общее
шифрование/расшифрование, подпись, аутентификацию или управление
production-ключами.

## Действия

| Действие | Результат | Вход по умолчанию |
|---|---|---|
| `pro/gost-kuznechik@v1` | Байты Кузнечик-CTR | Новые 32-байтовый ключ и 16-байтовый IV из ОС |
| `pro/gost-magma@v1` | Байты Магма-CTR | Новые 32-байтовый ключ и 8-байтовый IV из ОС |
| `pro/gost-streebog@v1` | Дайджест Streebog-256 или Streebog-512 | Новый 32-байтовый вход из ОС |

Каждое действие возвращает `algorithm`, `data`, `format`, `length` (число байтов
до текстового кодирования), `duration_ms` и `metrics`. В журнал записываются
только алгоритм, число байтов и длительность — никогда ключи, IV, исходные или
сгенерированные данные.

## Кузнечик и Магма

```yaml
steps:
  - use: pro/gost-kuznechik@v1
    with:
      length: 64
      format: base64
    outputs: random_payload

  - use: pro/gost-magma@v1
    with:
      length: 32
      format: hex
      key: ${{ env.GOST_TEST_KEY }}   # 64 hex-символа, необязательно
      iv: ${{ env.GOST_TEST_IV }}     # 16 hex-символов, необязательно
    outputs: test_payload
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `length` | `32` | Число генерируемых байтов, `1..1048576`; число или числовая строка |
| `format` | `hex` | `hex`, `base64` или `base64url` |
| `key` | Случайный из ОС | 32-байтовый ключ как 64 hex-символа |
| `iv` | Случайный из ОС | Кузнечик: 32 hex-символа; Магма: 16 |

Задайте и `key`, и `iv` для повторяемого результата. Если задан только один,
второй остаётся случайным, поэтому результат не воспроизводится. Фиксированные
значения предназначены для стандартных векторов и детерминированных тестов, а
не для хранения production-ключей. Секреты передавайте через `${{ env.* }}`, не
коммитьте их в YAML.

Используются `kuznechik-rs` CTR (NIST SP 800-38A, счётчик младших 32 бит) и
RustCrypto `ctr::Ctr64BE<Magma>`. Режимы ГОСТ Р 34.13 MVK, MAC/OMAC и
аутентифицированное шифрование не реализованы.

## Streebog-256 и Streebog-512

```yaml
steps:
  - use: pro/gost-streebog@v1
    with:
      size: 512                 # 256 (по умолчанию) или 512
      format: hex
    outputs: random_digest

  - use: pro/gost-streebog@v1
    with:
      size: 256
      data: "3132333435363738"  # входные байты hex ("12345678")
    outputs: known_digest
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `size` | `256` | `256` — дайджест 32 байта, `512` — 64 байта |
| `format` | `hex` | `hex`, `base64` или `base64url` |
| `data` | 32 случайных байта | Необязательный вход hex; пустая строка хеширует пустой массив |

Streebog — неключевая функция, параметров `key` и `iv` нет. Один и тот же
`data` всегда даёт один и тот же дайджест.

## Метрики

- `gost_operations` — все вызовы генерации/хеширования, включая отклонённые.
- `gost_bytes` — число сгенерированных байтов до текстового кодирования.
- `gost_errors` — ошибки валидации и источника случайности ОС.

Длительность вызова также попадает в общие агрегаты времени выполнения.

## Границы применения

Это генератор данных для нагрузочных тестов, **не сертифицированный
криптомодуль**. Стандартные векторы проверяют совместимость алгоритмов, но
соответствие требованиям ФСБ или ФСТЭК не заявляется. Для конкретной
государственной информационной системы нужна отдельная оценка: аудит
реализации, постоянное время выполнения, хранение ключей, разрешённые режимы и
операционные процедуры. Реализация Кузнечика документирует риск cache-timing и
не затирает внутреннее расписание раундовых ключей.

Практические сценарии и полный YAML-пример — в [посте о GOST](/blog/gost-random-data).
