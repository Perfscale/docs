## Обзор

Каждый прогон perfscale завершается каноническим документом в памяти —
**`report@v1`** — с идентичностью прогона, агрегатами по шагам, verdicts
thresholds и всеми зарегистрированными семействами метрик. **Репортеры**
рендерят этот документ в назначение: файл на диске, HTTP-endpoint или и то
и другое. Репортеры запускаются один раз, после завершения прогона, и
никогда не влияют на сам прогон.

Репортеры — фича **open-source движка**. Доступны с perfscale **v0.27.0**.

## Встроенные репортеры

| Репортер | Вывод | Доступность |
|---|---|---|
| `std/report/json@v1` | Канонический документ `report@v1` в pretty-printed JSON | v0.27.0+ |
| `std/report/junit@v1` | JUnit XML для CI: testsuite — это прогон, testcase на каждый шаг, и каждый проваленный verdict threshold добавляет падающий testcase `threshold: …` — CI-гейт читает только этот файл | v0.27.0+ |
| `std/report/html@v1` | Одна self-contained HTML-страница (тёмная тема, идентичность прогона, verdicts, таблица шагов со sparklines сэмплов, семейства метрик; весь CSS/JS инлайн, открывается офлайн, архивируется как CI-артефакт) | **следующий релиз** |
| `wasm:./path.wasm` | Кастомный WASM-репортер — см. [Свой репортер](/docs/concepts/custom-reporters) | v0.27.0+ |

## Настройка репортеров

Репортеры используют пошаговый паттерн `use:`/`with:` и объявляются в
`report.reporters` конфиг-файла:

```yaml
report:
  labels:
    testid: smoke              # штампуется на идентичности прогона
  reporters:
    - use: std/report/json@v1
      with: { path: report.json }
    - use: std/report/junit@v1
      with: { path: junit.xml }
    - use: std/report/json@v1
      with:
        url: https://collector.example.com/reports   # HTTP push
        headers:
          Authorization: "Bearer ${REPORT_TOKEN}"    # ${VAR} резолвится на хосте, никогда не логируется
        max_samples: 10000     # сколько сырых сэмплов шага включить
```

Каждому репортеру нужно **ровно одно назначение**:

- `with.path` — запись в файл. Относительные пути привязываются к файлу, в
  котором объявлены.
- `with.url` — HTTP push: тело отчёта отправляется POST'ом на URL. Значения
  заголовков в `with.headers` могут содержать `${VAR}`-ссылки на
  окружение; они резолвятся на стороне хоста и **никогда не логируются**.

Общие опции:

| Опция | По умолчанию | Описание |
|---|---|---|
| `with.path` / `with.url` | — | Назначение — ровно одно из двух |
| `with.headers` | — | Заголовки для HTTP push (допустимы `${VAR}`-ссылки) |
| `with.max_samples` | `100000` | Лимит сырых сэмплов на шаг; `0` отключает. Шаг, записавший больше, помечается `truncated: true` |

### Эквивалент в CLI

Флаг `--report` — сокращённая форма; флаг повторяемый, так что один прогон
может выдать несколько отчётов:

```bash
perfscale run -f test.yaml -c config.yaml \
  --report json:report.json \
  --report junit:junit.xml
```

`--report html:report.html` появится в следующем релизе. Когда подключён
`perfscale serve` (`--report http://…` или `report.url`), артефакт
`report@v1` дополнительно отправляется POST'ом на `<url>/api/v1/report`.

## Политика ошибок

- **Ошибки конфигурации — fail fast**: неизвестный репортер, отсутствующее
  назначение, незаданный `${VAR}` или незагружаемый WASM-модуль падают на
  lint/validate — до начала прогона.
- **Ошибки доставки — best-effort**: неудачный push в конце прогона
  логируется и считается в метрике `engine_report_errors`, но прогон
  завершается и сохраняет свой exit code.

## Схема `report@v1`

JSON-документ, который потребляет каждый репортер (`std/report/json@v1`
пишет его как есть; WASM-репортеры получают его как `report-json`).
Контракт стабилен и развивается **только аддитивно** внутри мажорной
версии.

**Единицы**: движок меряет в миллисекундах, но на проводе — **секунды**
(конвенция Prometheus): каждая длительность, квантиль и сырой сэмпл в
документе — в секундах. Одно исключение: `verdicts[].observed` говорит на
языке threshold'а — миллисекунды для duration-метрик, доля для `rate`,
абсолютное число для `count`.

### Верхний уровень

| Поле | Тип | Описание |
|---|---|---|
| `schemaVersion` | string | Всегда `"report@v1"` |
| `run` | object | Идентичность прогона (ниже) |
| `steps` | array | Агрегаты по шагам, в порядке объявления шагов теста |
| `verdicts` | array | Каждое вычисленное выражение threshold, pass или fail |
| `metrics` | array | Каждое зарегистрированное семейство метрик (встроенные + custom), записанные или нет |
| `seq` | null | Зарезервировано под будущие streaming-снапшоты; в отчётах конца прогона всегда `null` |
| `samples` | array | Зарезервировано под будущие streaming-снапшоты; всегда пусто |

### `run`

| Поле | Тип | Описание |
|---|---|---|
| `run_id` | string | Идентификатор прогона, сгенерированный движком |
| `engine` | string | `"native"`, `"k6"`, `"locust"` или `"jmeter"` |
| `perfscale_version` | string | Версия perfscale, создавшая отчёт |
| `vus` | number \| null | Виртуальные пользователи; `null`, когда форма нагрузки вне ведома CLI (k6-скрипты, staged/arrival прогоны) |
| `started_at` | string | Старт прогона, UTC ISO 8601 |
| `duration_s` | number | Длительность прогона по стенным часам, секунды |
| `labels` | object | Пользовательские метки (`report.labels` в конфиге / `--label` в CLI), интерполированные |

### `steps[]`

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | `name:` шага, или id действия, если шаг безымянный |
| `action` | string | Id действия, например `std/http@v1` |
| `count` | number | Вызовов за весь прогон |
| `failed` | number | Неуспешных вызовов |
| `rate` | number | Вызовов в секунду wall-clock времени прогона |
| `duration` | object | Блок квантилей — `avg`, `min`, `p50`, `p90`, `p95`, `p99`, `max` — все в секундах |
| `samples` | object \| отсутствует | Сырые сэмплы длительностей; присутствует, когда репортер включил их через `max_samples` |

`samples` содержит:

| Поле | Тип | Описание |
|---|---|---|
| `values` | number[] | Включённые сэмплы длительностей (секунды), в порядке записи |
| `truncated` | boolean | `true`, когда шаг записал больше сэмплов, чем поместилось в `values` |
| `recorded` | number | Сколько всего сэмплов записано, включая отброшенные сверх лимита |

### `verdicts[]`

| Поле | Тип | Описание |
|---|---|---|
| `threshold` | string | Метрика, по которой вычислялось выражение, например `http_req_duration` |
| `expression` | string | Выражение как написано, например `p95<500` |
| `pass` | boolean | Исход |
| `observed` | number | Фактическое значение агрегата — мс для duration-метрик, доля для `rate`, абсолютное число для `count` |

### `metrics[]`

Самоописываемые семейства метрик: каждая запись несёт метаданные реестра
плюс записанные серии. Сначала идут зарегистрированные семейства в порядке
регистрации; записанные, но незарегистрированные имена следуют за ними в
семействе `custom`.

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя метрики, например `http_req_duration` |
| `family` | string | Владеющее семейство (`http`, `llm`, …); `custom` для незарегистрированных имён |
| `kind` | string | `sample` \| `counter` \| `rate` \| `gauge` |
| `unit` | string | Единица из реестра |
| `description` | string | Описание из реестра |
| `recorded` | boolean | `false`, когда семейство объявлено, но ничего не записано — тогда серий нет |
| `series` | array | Записанные серии |

Какие поля значений у серии заполнены, зависит от kind семейства:

| Kind | Поля серии |
|---|---|
| `sample` | `quantiles` (мапа `"0.5"`/`"0.9"`/`"0.95"`/`"0.99"` → секунды), `count`, `sum` (секунды) |
| `counter` | `value` |
| `rate` | `total` (вызовов), `failed` |
| `gauge` | `value` плюс `ts` (point-in-time, RFC3339); серии сохраняют свои labels, например `gpu="0"` |
