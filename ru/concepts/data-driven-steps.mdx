## Обзор

Реалистичный сценарий не выполняет одни и те же шаги с одними и теми же
значениями на каждой итерации: логин один раз, лайки на части постов,
свой пользователь на каждый виртуальный VU, пауза с человеческим think
time. Perfscale покрывает это небольшим набором примитивов уровня шага —
**без скриптинга**:

| Примитив | Что делает |
|---|---|
| `if:` / `when:` | Выполнить шаг, только если условие истинно |
| `std/random@v1` | Сгенерировать одно число (integer или float) в output шага |
| `std/pick@v1` | Выбрать один элемент JSON-массива — из файла или из ответа |
| `${{ __vu__ }}` / `${{ __iter__ }}` | 1-based id текущего VU и его 0-based итерация |

Это обычные шаги, поэтому их output'ы проходят через ту же интерполяцию
`${{ ... }}`, что и всё остальное — случайное число может стать длительностью
sleep, индексом или вероятностным броском.

Полный пример — старт со stagger, свой пользователь на VU, вероятностный
лайк, случайный think time:

```yaml
steps:
  - use: std/random@v1
    when: "${{ __iter__ }} == 0"                 # stagger: только первая итерация
    with: { type: float, min: 0, max: 5 }
    outputs: startup_delay

  - use: std/sleep@v1
    when: "${{ __iter__ }} == 0"
    with: { seconds: "${{ startup_delay }}" }    # динамический sleep из output'а random

  - use: std/pick@v1
    with: { file: fixtures/users.json, index: "${{ __vu__ }}", index_offset: -1 }
    outputs: user                                # свой пользователь фикстуры на VU

  - use: std/http@v1
    with: { url: "https://api.example.com/feed" }
    outputs: feed

  - use: std/random@v1
    with: { type: integer, min: 0, max: 19 }
    outputs: post_index

  - use: std/pick@v1
    with: { from: "${{ feed.body.posts }}", index: "${{ post_index }}" }
    outputs: post                                # случайный пост из ответа

  - use: std/random@v1
    with: { type: float, min: 0, max: 1 }
    outputs: like_roll

  - use: std/http@v1
    when: "${{ feed.status }} == 200 && ${{ like_roll }} < 0.15"
    with:
      method: POST
      url: "https://api.example.com/posts/${{ post.id }}/like"
      headers: { Authorization: "Bearer ${{ user.token }}" }
```

## Условные шаги: `if:` / `when:`

Любой шаг принимает поле `if:` или `when:`. Это **эквивалентные алиасы**;
объявление обоих на одном шаге — **ошибка парсинга** — выберите одно имя и
используйте его последовательно.

Плейсхолдеры `${{ ... }}` и токены-генераторы `${...}` в условии раскрываются
первыми; результат вычисляется как:

- **сравнение** — `==`, `!=`, `<`, `<=`, `>`, `>=`; числовое, когда обе
  стороны парсятся как числа, иначе строковое (литералы можно брать в
  `'…'`);
- или **голое значение** — false, когда оно пустое, `false`, `0` или `null`,
  иначе true.

Клаузы комбинируются через `&&` и `||` (`&&` связывает сильнее; скобок нет):

```yaml
  - use: std/http@v1
    when: "${{ feed.status }} == 200 && ${{ like_roll }} < 0.15"
    with: { method: POST, url: "https://api.example.com/posts/1/like" }
```

**Пропущенный** шаг не создаёт output, не пишет метрик и не трогает
`__last__` — следующие шаги видят output последнего реально выполненного
шага. Поэтому условия, зависящие от output'а пропущенного шага, видят
предыдущее значение; значения, которые вы проверяете в `when:`, сохраняйте
под явными именами `outputs:`.

Типичные применения: `when: "${{ __iter__ }} == 0"` для per-VU setup (залогиниться
один раз и переиспользовать токен), вероятностные броски, как в примере выше,
и защита последующего запроса проверкой предыдущего статуса.

## `std/random@v1`

Генерирует одно числовое значение. Output — само число, готовое к
интерполяции `${{ name }}` в следующих шагах:

```yaml
steps:
  - use: std/random@v1
    with: { type: integer, min: 1, max: 100 }
    outputs: quantity
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `type` | string | **обязателен** | `integer` (включительно `[min, max]`) или `float` (`[min, max)`) |
| `min` | number | **обязателен** | Нижняя граница; не должна превышать `max` |
| `max` | number | **обязателен** | Верхняя граница; не должна быть ниже `min` |

Равные границы возвращают эту константу. `seed:` прогона делает
последовательность воспроизводимой; каждый VU получает свою
детерминированную последовательность.

В отличие от токена-генератора `${rand(a,b)}` — который раскрывается внутри
одного сообщения — `std/random@v1` это **шаг**: значение попадает в
именованный output, так что следующие шаги могут его читать, проверять в
`when:` и подавать в параметры, куда одна интерполяция не достаёт.

## Динамические sleep

`std/sleep@v1` принимает число или строку для `ms` / `seconds`, а значения
`${{ ... }}` резолвятся до выполнения action — так что output `std/random@v1`
становится think time напрямую:

```yaml
steps:
  - use: std/random@v1
    with: { type: float, min: 3, max: 7 }
    outputs: think_time
  - use: std/sleep@v1
    with: { seconds: "${{ think_time }}" }
```

Строка, не являющаяся числом после раскрытия, роняет шаг.

## Per-VU переменные

Два встроенных значения показывают, где выполняется шаг:

- `${{ __vu__ }}` — **1-based** id этого VU;
- `${{ __iter__ }}` — **0-based** счётчик итераций этого VU

(эквиваленты `__VU` / `__ITER` из k6). Сохранённый output с таким же именем
побеждает, так что не называйте свои `outputs:` `__vu__` или `__iter__`.

Это строительные блоки для шардирования фикстур по VU
(`index: "${{ __vu__ }}", index_offset: -1` отображает id VU на zero-based
элементы массива, ровно `(VU-1) % length`) и для логики «один раз на VU»
через `when: "${{ __iter__ }} == 0"`.

## `std/pick@v1`

Выбирает один элемент JSON-массива — случайный пост из ответа feed или
тестового пользователя из файла фикстур:

```yaml
steps:
  - use: std/pick@v1
    with: { file: fixtures/users.json, index: "${{ __vu__ }}", index_offset: -1 }
    outputs: user
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `from` | array или string | одно из `from`/`file` | Массив или строка с JSON-массивом (`"${{ feed.body.posts }}"`) |
| `file` | string (путь) | одно из `from`/`file` | Файл с JSON-массивом, парсится один раз на процесс и кешируется по `(mtime, size)`, как `std/file-read@v1`. Требует `allow_file_actions: true`, подчиняется `fs_root` |
| `index` | integer или string | random | Индекс элемента, с обёрткой по модулю длины массива. Пропущен → равномерно случайный |
| `index_offset` | integer или string | `0` | Знаковое смещение, применяемое к `index` **до** обёртки; отрицательные значения тоже оборачиваются |

**Output**: сам выбранный элемент, так что `${{ user.token }}` спускается
внутрь напрямую.

Заметки:

- Чтения `file` делят **общий на процесс JSON-кеш** с `std/read-json@v1` —
  первая итерация платит чтение и парсинг, следующие итерации всех VU
  попадают в RAM.
- Опустите `index` для равномерно случайного выбора (воспроизводимого под
  `seed:` прогона) или сгенерируйте индекс явным шагом `std/random@v1`,
  когда сам индекс нужен как output.
- Документ, не являющийся JSON-массивом, пустой массив или нецелый `index`
  роняют шаг.

## `std/pick` vs `@std/json` vs литеральные пути

Три механизма работают с JSON-данными — они дополняют друг друга, а не
пересекаются:

- **Литеральные пути в телах** — `${{ feed.body.posts[0].id }}` в `with:` /
  `check:` — парсят строковый лист как JSON по требованию и идут по
  *фиксированному* jq-style пути. Индекс в `[0]` — **литерал**: он не может
  прийти из переменной. Используйте их, когда позиция известна на момент
  написания теста.
- **`std/pick@v1`** — ответ, когда индекс **динамический**: id VU,
  случайный бросок, значение, вычисленное предыдущим шагом. Он выбирает
  элемент и отдаёт его как output шага, в который спускаются следующие шаги.
- **`@std/json@v1`** — *библиотека* токенов-генераторов
  (`${json.read(...)}`, `${json.pick(...)}`), раскрывающихся внутри строк
  payload'а, для значений из файлов, вставляемых прямо в сообщение без шага.
  См. [Библиотеки](/docs/concepts/libraries).

Эвристика: фиксированный путь в файле → `std/read-json@v1` или
`${json.read(...)}`; фиксированный путь в ответе → литеральный путь в теле;
динамический выбор из массива → `std/pick@v1`.
