## Базовый URL

Все эндпоинты обслуживаются Rust BFF:

```
http://localhost:8090/api/v1
```

**OpenAPI-спецификация:** полный машиночитаемый контракт (все 100 путей, схемы запросов и ответов, схемы безопасности) генерируется [utoipa](https://github.com/juhaku/utoipa) из исходного кода BFF и доступна для скачивания:

[Скачать openapi.json](/api-reference/openapi.json)

На живом развёртывании также работает интерактивный **Swagger UI** по адресу `/swagger-ui/` на хосте BFF (например, [http://localhost:8090/swagger-ui/](http://localhost:8090/swagger-ui/)). Эта страница — краткий обзор; точные типы полей и значения enum смотрите в спецификации.

## Аутентификация

API поддерживает два типа Bearer-учётных данных, передаваемых в заголовке `Authorization`:

```
Authorization: Bearer <token>
```

**Персональные API-токены (`psk_…`)** — рекомендуемый способ обращения к API из скриптов и CI. Токены создаются для конкретного пользователя, поддерживают срок действия и тонкие scope'ы, управляются через `/api/v1/api-tokens` (см. раздел [API-токены](#api-токены)). Открытое значение токена показывается только один раз при создании. Если scope'ы токена не покрывают операцию, возвращается `403`.

**Keycloak JWT** — короткоживущий access token, выданный Keycloak. Приложение Next.js получает его автоматически через next-auth. При прямых обращениях к API используйте ROPC grant:

```bash
curl -X POST http://localhost:8080/realms/perfscale/protocol/openid-connect/token \
  -d "grant_type=password" \
  -d "client_id=perfscale-site" \
  -d "client_secret=$CLIENT_SECRET" \
  -d "username=demo@perfscale.ru" \
  -d "password=demo1234"
```

**Машинные токены (`machine_auth`)** — M2M-токены, получаемые из Keycloak по grant'у `client_credentials`. Они несут claim `tenant_id`, привязывающий машину к её workspace, и предназначены для **агентов** (ping машин, приём OTel-метрик), а не для пользовательского доступа к API.

## Биллинговый барьер

Развёртывания с включённым биллингом (`BILLING_ENFORCE=true`, например perfscale.ru) требуют активной платной подписки. Тенанты без неё получают на все операции `/api/v1/*`:

**`402 Payment Required`**

```json
{
  "code": "PAYMENT_REQUIRED",
  "message": "An active paid subscription is required to use this endpoint"
}
```

Исключения (доступны всегда): `GET /api/v1/auth/me`, `POST /api/v1/contact`, `POST /api/v1/users/provision`, `GET /api/v1/tenants`, `POST /api/v1/tenants/switch`, `GET /api/v1/tenants/billing-status`, `GET /api/v1/tenants/payments`, `POST /api/v1/tenants/subscription/cancel`, `POST /api/v1/tenants/subscription/resume`, а также принятие приглашений. На развёртываниях, где биллинг отключён полностью, биллинговые эндпоинты возвращают `503` с кодом `BILLING_DISABLED`.

## Auth

### GET /api/v1/auth/me

Возвращает идентификационные данные текущего аутентифицированного пользователя, декодированные из JWT.

**Ответ `200 OK`**

```json
{
  "sub": "a1b2c3d4-...",
  "email": "demo@perfscale.ru",
  "name": "Demo User",
  "preferred_username": "demo",
  "roles": ["member"]
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `sub` | string | UUID пользователя в Keycloak |
| `email` | string? | Адрес электронной почты |
| `name` | string? | Отображаемое имя |
| `preferred_username` | string? | Имя пользователя в Keycloak |
| `roles` | string[] | Realm-роли, назначенные пользователю |

|---|---|
| `GET /api/v1/machines` | Список машин (с пагинацией) |
| `POST /api/v1/machines` | Зарегистрировать машину вручную |
| `GET /api/v1/machines/:id` | Детали машины |
| `DELETE /api/v1/machines/:id` | Удалить машину (`204`) |
| `PATCH /api/v1/machines/:id/status` | Изменить статус (`online` / `offline` / `maintenance`) |

|---|---|

| `POST /api/v1/tasks` | Запустить выполнение теста (`202 Accepted`) |
| `GET /api/v1/tasks/:id` | Детали задачи с метриками |
| `DELETE /api/v1/tasks/:id` | Отменить ожидающую или выполняющуюся задачу (`204`) |
| `GET /api/v1/tasks/:id/log` | Сохранённый лог завершённого прогона |
| `GET /api/v1/tasks/:id/otel-metrics` | Агрегированные OTel-метрики прогона |
| `GET /api/v1/tasks/:id/otel-timeseries` | Временные ряды OTel-метрик прогона |

**POST /api/v1/tasks — тело запроса**

```json
{
  "testId": "t_01"
}
```

**Ответ `202 Accepted`**

```json
{
  "id": "task_02",
  "status": "pending"
}
```

Отслеживайте прогресс через `GET /api/v1/tasks/:id`.

**Запись задачи**

```json
{
  "id": "task_01",
  "test_id": "t_01",
  "status": "passed",
  "p50": 142,
  "p95": 310,
  "p99": 490,
  "error_rate": 0.002,
  "requests_per_sec": 230.5,
  "total_requests": 6900,
  "started_at": "2025-01-15T10:05:00Z",
  "finished_at": "2025-01-15T10:05:30Z"
}
```

### POST /api/v1/test/run

Разовый запуск: отправить тест на конкретную машину без предварительного создания постоянной задачи. Обязательные поля — `machine` и `test`; опционально `configuration` и `transport` (`sse` | `ws` | `long_polling`). В ответе URL живого стрима рекламируется в `stream.<machineId>.url`.

### GET /api/v1/tasks/:id/log-stream

Живой лог-стрим выполняющейся задачи по **Server-Sent Events**
(`text/event-stream`). `:id` принимает UUID задачи или её публичный id;
аутентификация — обычный Bearer-токен.

Каждый `data:`-фрейм несёт одно событие задачи в JSON:

```json
data: {"type": "log", "source": "out", "text": "running (01m00.0s), 1/1 VUs"}
```

| `type` | Полезная нагрузка | Терминальное |
|--------|-------------------|--------------|
| `log` | `source` (`out`/`err`), `text` — одна строка вывода | нет |
| `done` | `task` — финальная запись задачи с метриками | да |
| `error` | `message` — неустранимая ошибка запуска | да |

После терминального события стрим завершается. Если прогон закончился до
подключения (или живой стрим уже недоступен), эндпоинт сразу отвечает одним
событием `done`, построенным из актуальной записи задачи.

### GET /api/v1/tasks/:id/ws

Тот же живой стрим по **WebSocket** — альтернативный транспорт, выбираемый
`"transport": "ws"` при запуске прогона (ответ тогда рекламирует этот URL в
`stream.<machineId>.url`). Аутентификация, разрешение id и семантика фолбэка
полностью совпадают с SSE-эндпоинтом.

- Каждое событие задачи приходит одним **текстовым сообщением** с тем же
  JSON, что в SSE `data:`-фреймах выше.
- После терминального (`done`/`error`) сообщения сервер закрывает сокет с
  кодом **1000** (нормальное закрытие).
- Сервер пингует каждые ~30 с и отключает клиентов с просроченным pong;
  отвечайте на ping pong'ом (любой стандартный WS-клиент делает это сам).
- Неизвестные или чужие id задач отклоняются обычными HTTP `404`/`401` до
  апгрейда, поэтому неудачный handshake несёт JSON с ошибкой.

`"transport": "sse"` (по умолчанию) ведёт на SSE-эндпоинт выше;
`"transport": "long_polling"` не реализован и пока откатывается на SSE.

## Ответы с ошибками

Все ответы с ошибками следуют общему формату `ApiError`:

```json
{
  "code": "NOT_FOUND",
  "message": "Task task_99 does not exist"
}
```

| Статус | Значение |
|--------|----------|
| `400` | Некорректное тело запроса |
| `401` | Отсутствующий или истёкший токен |
| `402` | Требуется оплата — нет активной платной подписки (см. [Биллинговый барьер](#биллинговый-барьер)) |
| `403` | Токен действителен, но прав недостаточно — также возвращается, когда scope'ы `psk_`-токена не покрывают операцию |
| `404` | Ресурс не найден |
| `409` | Конфликт (например, hostname машины уже зарегистрирован) |
| `500` | Внутренняя ошибка сервера |
| `503` | Функция недоступна (например, `BILLING_DISABLED` на развёртываниях без биллинга) |
