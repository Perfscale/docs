## Base URL

All endpoints are served under `{base_url}/api/v1`. For the hosted cloud, `{base_url}` is `https://perfscale.ru`; on self-hosted deployments it is the public origin of your gateway.

The complete machine-readable contract is available as OpenAPI: [openapi.json](/api-reference/openapi.json). On self-hosted deployments the BFF also serves Swagger UI at `/swagger-ui/` on its own port.

## Authentication

The API supports two Bearer credential types, passed in the `Authorization` header:

```
Authorization: Bearer <token>
```

**Personal API tokens (`psk_…`)** — the recommended way to call the API from scripts and CI. Tokens are created per user, support optional expiry and fine-grained scopes, and are managed under `/api/v1/api-tokens`. The plaintext secret is shown exactly once at creation. A token whose scopes do not cover an operation receives `403`.

**Keycloak JWT** — a short-lived access token issued by Keycloak. The web app obtains it automatically when you sign in. When calling the API directly, use the ROPC grant:

```bash
curl -X POST {base_url}/realms/perfscale/protocol/openid-connect/token \
  -d "grant_type=password" \
  -d "client_id=perfscale-site" \
  -d "client_secret=$CLIENT_SECRET" \
  -d "username=demo@perfscale.ru" \
  -d "password=demo1234"
```

**Machine tokens** — M2M tokens obtained from Keycloak via the `client_credentials` grant. They bind a machine to its workspace and are intended for **agents** (machine ping, OTel ingestion), not for end-user API access.

## Billing

An active subscription is required: on the paid instance the API responds with `402 {"code":"PAYMENT_REQUIRED"}` to `/api/v1/*` operations for tenants without an active subscription. Exceptions: auth/me, tenant and payment management, invitations, subscription.

**`402 Payment Required`**

```json
{
  "code": "PAYMENT_REQUIRED",
  "message": "An active paid subscription is required to use this endpoint"
}
```

Exempt endpoints (always available): `GET /api/v1/auth/me`, `POST /api/v1/contact`, `POST /api/v1/users/provision`, `GET /api/v1/tenants`, `POST /api/v1/tenants/switch`, `GET /api/v1/tenants/billing-status`, `GET /api/v1/tenants/payments`, `POST /api/v1/tenants/subscription/cancel`, `POST /api/v1/tenants/subscription/resume`, and invitation accept.

## Error responses

All error responses follow the common `ApiError` envelope:

```json
{
  "code": "NOT_FOUND",
  "message": "Task task_99 does not exist"
}
```

| Status | Meaning |
|--------|---------|
| `400` | Invalid request body |
| `401` | Missing or expired token |
| `402` | Payment required — no active paid subscription (see [Billing](#billing)) |
| `403` | Token valid but insufficient permissions — also returned when a `psk_` token's scopes don't cover the operation |
| `404` | Resource not found |
| `409` | Conflict (e.g. machine hostname already registered) |
| `500` | Internal server error |
| `503` | Feature unavailable (e.g. `BILLING_DISABLED` on deployments without billing) |
